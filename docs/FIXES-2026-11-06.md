## Known gaps not addressed
- Dark mode (static palette), push notifications, report export (PDF/Excel), per-role mobile dashboards not exercised on a device.
- 7 remaining npm advisories sit in the Expo toolchain (`expo-router`/`query-string` etc.) and need an Expo SDK major upgrade.
- Individual tokens are not revocable on logout (they expire in 8h); deactivation and password change do revoke.
- Drizzle `meta/*_snapshot.json` was not regenerated for 0002; run `drizzle-kit generate` carefully before the next schema change.
- Auto mode sends sequentially inside the request; very large classes may be slow (use manual mode or add a queue).

# Second pass — defects found by the full audit (same day)

The audit in `docs/AUDIT-2026-11-06.md` was run against a disposable PostgreSQL 16 database with the real API, web build and Expo export. It found and fixed the items below. Everything listed was re-verified by execution; nothing here is a code-review-only claim.

## Fixed in this pass

| Finding | Fix | How it was verified |
|---|---|---|
| **The mobile app had no browser target at all** — `react-native-web`, `react-dom`, `@expo/metro-runtime` were missing, `app.json` had no `web.output`, and two native-only modules were used unconditionally | Added the three dependencies (SDK 57 versions), `web.output: "static"` + `baseUrl: "/mobile"`, platform splits `src/services/storage(.web).ts` and `src/components/AbsenceDatePicker(.web).tsx`, `app/+html.tsx` for the document shell, and `scripts/mobile-export.mjs` (`npm run mobile:export`) which bakes the relative `/api` base | `npx expo export --platform web` → 18 static routes; served by Express at `/mobile`, `/mobile/login`, `/mobile/attendance` (200), bundle 1.7 MB (200); Android Hermes export still builds |
| **Database errors leaked SQL, parameters and a bcrypt hash** in 500 responses | `server.ts` now walks the error chain (`findPostgresError`) and maps `23505/23503/23502/22P02` to safe 4xx messages; `duplicateMessage()` lives in `utils/http.ts` with a unit test | Reproduced before/after with a duplicate roll number: raw SQL → `400`/`409` with a human message; `npm test` covers the mapping |
| **Sign-out did not revoke the token** (valid for the remaining 8 h) | `users.session_version` (migration `0003`), signed into every JWT, compared on every request; bumped by logout, `POST /auth/revoke-sessions`, password change and admin reset | `login → me 200 → logout → me 401 "Your session was signed out"`; a fresh login works |
| **No SMS dashboard in the portal** although the API existed | `apps/web/src/components/SmsDashboardPage.tsx` + nav entries for HOD/Principal/Admin/Super Admin | Typecheck + build; responsive filters, pagination, masked numbers |
| **"Reports" nav opened a raw history table; no date-range reporting or export** | `GET /api/admin/reports/attendance?from&to` (department/subject/daily/student aggregates, HOD scoped) and `ReportsPage.tsx` with CSV export for each section | `test:permissions` asserts HOD gets 200; typecheck/build |
| **Workspace search box filtered nothing** | `quickSearch` is threaded into `DataPage` as an initial filter | Typecheck + build |
| **Settings page was static text and the portal had no password change** | `SecurityPage.tsx` (change password, sign out all sessions, sign out) replacing the placeholder panel; "My Security" entries for every role | Typecheck/build; `/auth/change-password` and `/auth/revoke-sessions` verified by API probe |
| **Duplicate/invalid records returned 500 instead of a conflict** | see the error-mapping row | `permission-smoke-test.mjs` asserts no SQL in the message |
| **`scripts/smoke-test.mjs` failed on any date more than 7 days after the seed** (hard-coded `2026-10-04` against the faculty edit window) | Defaults to today in IST; the student-threshold assertion now reports the numbers it saw | `npm run test:smoke` passes end to end |

| **Preview/dev server hard-coded two Manus hostnames** (`allowedHosts`) so any other preview URL was rejected; a second `vite.preview.config.ts` duplicated the config | `vite.config.ts` → `allowedHosts: true`, ports/proxy documented, preview config deleted | Vite serves `/`, `/api` proxy login 200, `/mobile` through the same origin |
